## mcm_core.py 提供的 API

```python
ev = mc.evaluate(X, signs, log_cols)             # 熵权TOPSIS，返回 score/权重表/D±
coefs, r2 = mc.fit_quad_by_group(x, ys)          # 分组二次拟合
f = mc.make_quad_fn(coefs, lo, hi)               # 包成 f(x,group)，含顶点截平保单调
ok, msg = mc.check_alloc_feasible(B, m, 10, 100) # 总量可行性自检
q = mc.alloc(B, w, qmin, qmax, floor_all=True)   # 比例分配+截断+迭代再分配（不动点500步）
res = mc.bilevel_optimize(unit_gain, weight_of, ...)  # 通用双层迭代（网格坐标上升）
res = mc.credit_optimize(g, p, risk, churn_fn, B)     # 信贷定价薄封装
df = mc.spearman_report([(名, x, y, '+')])       # 秩相关方向+显著性批量核对
plt = mc.setup_mpl()                             # 中文绘图
```

换赛题只改 `unit_gain` 与 `weight_of` 两个函数，外层框架不动。

## 三条写进 README 的坑

1. 规模指标不对数化 → 极差归一化把对象压到 0 附近，评价没区分度（`log_cols` 解决）。
2. 最差一档提前剔除 → 理想解失去最差参照，分值整体偏移。全样本评价，决策阶段再筛。
3. 总量放不满当成结论 → `m·qmin > budget` 是约束不相容，`check_alloc_feasible` 先报。
